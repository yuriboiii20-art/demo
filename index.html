SIMULATION ENGINE CAPABILITIES

Designed to Test Payment Failures & Stuck Recovery

When building payment recovery tools, webhooks, or automated reconciliation systems, you need reliable failure scenarios. This demo reproduces the most frustrating real-world payment states:

⏳

Stuck in Pending / Hang

Simulates an acquirer network freeze where payment stays in PENDING indefinitely without webhook response.

🛑

Card Declined / 402

Simulates insufficient funds or high-risk block throwing an immediate ERR_CARD_DECLINED response.

⏱️

Bank Gateway 504 Timeout

Simulates a slow bank server that hangs for 8 seconds before dropping connection with ERR_GATEWAY_TIMEOUT.

🔒

3DS / OTP Verification Failed

Simulates 3D Secure / OTP verification failure or two-factor session expiration during bank redirect.

✅

Payment Authorized (Success)

Standard successful 200 OK authorized payment to compare normal vs edge-case checkout flows.

💡 How to hook your recovery solution into this demo:

This demo emits window custom events that your external code can listen to:

window.addEventListener('payment_event', (event) => {
  const { status, transactionId, errorCode, amount } = event.detail;
  console.log('Payment Event Received:', status, errorCode);
  // Trigger your recovery webhook or auto-reconciliation engine here
});

// Or programmatically resolve a stuck payment:
window.PaymentDemoGateway.resolveStuckPayment('success'); // or 'cancel'
